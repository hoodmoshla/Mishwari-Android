# فكرة مشواري وحالة متطلباته

## الفكرة التي نبنيها

مشواري ليس تطبيق خرائط ولا قائمة تسوق فقط. هو **ذاكرة محلية للطلبات مرتبطة بالأماكن**: تسجل احتياجك اليوم، وتربطه بمحافظة أو مديرية أو سوق أو محل في اليمن، ثم تجهز مشوارك يدويًا، ويذكرك التطبيق بالطلبات غير المنجزة عند دخول نطاق نقطة دقيقة اخترتها. الأولوية لسلامة البيانات، واعتمادية التذكير، وقلة استهلاك البطارية، والخصوصية، وتجربة عربية سهلة.

المواصفات الأصلية كاملة محفوظة في [ORIGINAL_REQUIREMENTS.ar.txt](ORIGINAL_REQUIREMENTS.ar.txt). لا تُستبدل هذه المواصفات بقائمة الميزات الحالية، ولا يعني إنجاز الكود أن قبول الهاتف قد اكتمل.

## ما نحافظ عليه

تطبيق أندرويد أصلي Kotlin وCompose وMaterial 3، مع Room/SQLite وFlow، وعربية وRTL ومظهر فاتح وداكن. لا حساب أو اشتراك أو خادم خاص أو مفتاح API إلزامي. لا نستبدل التطبيق أو نبدأ من الصفر. المصدر الأساسي المستودع الخاص `hoodmoshla/Mishwari-Android`، والعمل على `codex/initial-implementation` مع commits واضحة وGitHub Actions. هوية التطبيق `ye.mishwari`؛ لا تُنقل أسرار أو مفاتيح تطبيق آخر إليه.

## مطابقة المتطلبات

| المتطلب الأصلي | التنفيذ الموجود | ما لا يزال يحتاج قبولًا أو تطويرًا |
|---|---|---|
| الرئيسية والطلبات | مؤشرات غير المنجز/الوجهات/المكتمل، بحث وتصفية وإضافة سريعة وحالة الأذونات والسفر | لا يوجد جدول لمشاوير مستقبلية متعددة مؤرخة؛ الموجود رحلة واحدة نشطة يدويًا |
| بيانات الطلب | العنوان والوصف والفئة والكمية والسعر والملاحظات والأولوية والاستحقاق والحالة والصورة والربط بمكان؛ تعديل وحذف وإكمال مستقل | استكمال اختبار كل الحقول على الهاتف مع الخط الكبير والشاشة الصغيرة |
| دليل اليمن | نموذج هرمي، إضافة يدوية، بيانات OCHA/HDX اختيارية ومصدر وتاريخ، استيراد تحديثات | الدليل أسماء ورموز فقط وليس سجلًا شاملًا للأسواق والمحلات أو حدودًا/إحداثيات |
| اختيار المكان | إحداثيات يدوية أو MapLibre/OSM أو مكان بلا إحداثيات | فحص الخريطة وOpenGL على هاتف حقيقي؛ لا خرائط غير متصلة مضمونة |
| تنبيه الوصول | Google Geofencing، إشعار مجمّع، فتح طلبات المكان، منع التكرار، نطاق قابل للتعديل، حد 90 نقطة ذات صلة، استعادة التسجيل | **لم يثبت بعد توليد أحداث وصول فعلية في الخلفية**؛ لا يكفي نجاح بناء APK أو حقن ENTER/EXIT في الاختبارات |
| وضع السفر | اختيار محافظة/وجهة صراحةً، ضم الطلبات والأماكن التابعة، عرض الجاهزية وإنهاء السفر | لا استنتاج تلقائي للوجهة أو توجيه ملاحي؛ ليست هذه شروط الإصدار الأول |
| العمل المحلي | حفظ وإدارة وبحث ونسخ ودليل محلي بلا إنترنت | خرائط الشبكة وخدمة Google قد تحتاجان اتصالًا؛ لا نعد بتنبيه جغرافي مضمون دون الشبكة |
| الصور والنسخ | صورة منتقاة محليًا، JSON بحدود حجم وصور مضمنة ودمج ذري للبيانات دون تفعيل المراقبة المستوردة | النسخ غير مشفرة؛ لا مزامنة سحابية، واختبار استعادة على هاتف مستقل ما زال مطلوبًا |
| الصوت والمشاركة | إضافة اختيارية لمسودة نصية تُراجع قبل الحفظ، دون حفظ تلقائي أو تخمين للمكان | الإملاء يعتمد على تطبيق التعرف المثبت وقد يستخدم الشبكة؛ لا تسجيل صوت محفوظ ولا استقبال صور/ملفات مشاركة |
| الأمان والأذونات | بيانات محلية ونسخ أندرويد السحابي معطّل، شرح الخلفية، رفض الأذونات لا يمنع القوائم | مراجعة ميدانية للبطارية وDoze وإعادة التشغيل وغياب خدمات Google |
| الاختبارات والتسليم | اختبارات وحدات وSQLite وCompose وReceiver وWorker، Lint وAPK اختباري عبر CI | اختبارات الجهاز المباشرة لم تُشغّل؛ Release الإنتاجي ينتظر مفتاحًا دائمًا معتمدًا خاصًا بمشواري |

## شروط اعتبار الوظيفة الأساسية موثوقة

1. اجتياز [خطة الهاتف](../TESTING.md): الوصول مع الشاشة مغلقة، الإشعار المجمّع، فتح الوجهة، الخروج والعودة ومنع التكرار، إكمال بعض الطلبات، إعادة التشغيل وتغير الأذونات والموقع والبطارية والشبكة.
2. حفظ الطلبات والصور والعلاقات بعد إغلاق التطبيق وإعادة تشغيل الهاتف، واختبار تصدير/استيراد فعلي قبل اعتماد البيانات المهمة.
3. توثيق الجهاز وإصدار أندرويد وخدمات Google والنتيجة الفعلية. عدم الوصول إلى جهاز ليس نجاحًا مفترضًا ولا سببًا لتغيير التقنية دون مبرر.
4. اعتماد مفتاح توقيع إنتاجي خاص بمشواري والتحقق من الشهادة قبل توزيع Release. لا إنشاء مفتاح بديل أو استخدام سر مشروع آخر.
